1 The challenge

Subject practice is often lecture-heavy and low on hands-on STEM. Tools are fragmented, progress is hard to resume, and many Bangladesh labs run on shared phones with flaky internet and no expensive hardware.

2 Objectives

  • Turn learning objectives into playable missions.
  • Keep every lesson on a clear Canvas 2D stage.
  • Restore hub vs in-mission state after reload.
  • Offer optional AI that never blocks offline play.
  • Scale 28 subjects from one shared engine.

3 Methodology

1 Map curriculum to one mission idea.
2 Design rules, rewards, feedback.
3 Build Canvas 2D + save-v2 persist.
4 Iterate via LEVEL_QA uniqueness-pass.

4 Why this product

  • 28 titles, one engine, one pedagogy layer.
  • Offline-first save-v2; login is optional.
  • Strict বাংলা / English modes, no mixed UI.
  • Mastery stays locked until fluency hits 80%.
  • 3D reserved for the Force Fighter playground only.

14 Finished depth

25 uniqueness-pass missions in 16 titles. Deepest (M1 to M3): Force Fighter, Chemistry Lab, Bio Explorer, Web Dev Studio. ICT has M1 to M2. Twelve catalog titles still lack a pass.

15 2D vs 3D

All graded levels are Canvas 2D for clarity, load time, and scale. Three.js is only the Force Fighter free-play playground (spawn, push, ice/friction). 3D inside lessons is later, not now.

20 Security and playground

Security: GROQ_API_KEY stays in server .env. Python proxy. local-fallback if chat is down. Filament is separate from the game client.

3D playground: Force Fighter only. Spawn cars, crates, rocks. Drag to push. Switch ice and friction. Not used in graded levels.
